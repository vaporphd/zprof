01 / НАКАТ

Как профиль ложится на проект

zprof init сканирует директорию по detect.yaml каждого overlay, показывает найденное в визарде (high-confidence — предвыбраны), и передаёт выбор в apply-движок. Дальше — семь шагов, строго по порядку. Кликни шаг: справа подсветятся файлы, которые он создаёт.

Движок apply/engine.go
  1. base-агенты → .claude/agents/ Без namespace. gates/* пропускаются, если не задан --with-gates. Модель из frontmatter резолвится через реестр алиасов.
  2. overlay-агенты → .claude/agents/ Если overlay'ев ≥2 — имена namespace-ятся коротким ником: implementer → implementer-ios.
  3. AGENT_LOOP.md — тонкий роутер Только базовый router-блок: таблица «ключевые слова → workflow-файл». Никакого overlay-контента.
  4. workflows/<template>.md По одному файлу на уникальный loop_template. Базовый workflow + loop.md каждого overlay как отдельные managed-блоки.
  5. CLAUDE.md — 5 типов блоков doctrine (base) + stack-config на overlay + авто-таблицы Consilium (роль→агент→источник), Executing (агент→зона файлов) и Stop list — сводка необратимого, на чём раннер обязан остановиться и спросить.
  6. state-файлы Создаются только если отсутствуют — существующие не трогаются. --minimal выключает docs/.
  7. .gitignore + .zprof.yaml Дописывает thoughts/, .zprof/runs/, бэкап-маски и gitignore-вклад каждого overlay. Манифест фиксирует overlay'и в порядке приоритета и managed_agents — что zprof записал сам, чтобы на следующем apply убрать упразднённое и не тронуть твоё.

↓ всё, что снаружи маркеров — твоё, не трогается

zprof sync перерисовывает только содержимое между маркерами. Если внутри блока нашлась ручная правка — три режима: overwrite (с .bak), preserve, interactive.

02 / ЦИКЛ

Агентский цикл и где он течёт

Каждый Task() возвращает финальное сообщение сабагента прямо в main-контекст. Наивный пайплайн из 5–7 агентов по 3–5k токенов = 15–35k мусора за итерацию. Через 3–4 итерации main перегружен, компакция рвёт continuity. Нажми кнопку — увидишь разницу.

Но прятать вывод мало: пока петлю крутит main — читает роутер, выбирает маршрут, диспатчит по одному — она копит маршрутные решения и осколки задачи. Поэтому контроллер цикла переехал целиком в task-runner. Граница: мутация кода — раннеру, git и чтение — main.

режим: изоляция включена — main видит одну схему на весь pipeline
15 000–35 000токенов / итерация без изоляции
~150токенов на один dispatch (T1)
≤500токенов на весь pipeline (T3)
≤120символов на строку run-лога

Четыре уровня изоляции — работают вместе

T1

Terse handoff

У каждого агента в frontmatter обязательный return_format. Тело промпта кончается жёстким правилом: analysis и rationale — только в artifact, финальное сообщение = ровно схема. Скалярные extras (confidence, notes) разрешены, оркестратор парсит только базовые поля.

T2

Artifact-first

Всё содержательное живёт файлами: plan-N.md, docs/adr/, reports/, todo.md. Main перечитывает только followup.md + top-3 из lessons.md. Планы и ADR читаются точечно, когда нужно решать.

T3

Task-runner

Один агент владеет всем циклом: сам роутит, сам гоняет цепочку, сам ведёт журнал, отдаёт main одну схему. Поглотил оба прежних оркестратора — глубина вложенности не выросла. Упёрся в стоп-лист → verdict=blocked с вопросом, ответ уходит новому раннеру через resume_from + decision.

T4

Workflow tool

Для fan-out на ≥5 агентов (мульти-гипотезы в RE, sweep по файлам, миграции) loop.md предписывает дёрнуть Workflow(...) вместо параллельных Task'ов. Исполняется в фоне, main получает одно агрегированное сообщение; isolation: worktree разводит параллельных implementer'ов по файлам.

Три правила, которые main обязан соблюдать

  • Не цитировать вывод сабагента. Только пересказ схемы: verdict + one_line + путь к artifact. Никогда не вставлять фрагменты artifact'а в разговор.
  • ≤3 строки в followup.md после каждого dispatch'а — записал status, дропнул ответ сабагента из рабочей памяти.
  • Никогда не диспатчить роли напрямую. implementer, tester, architect — собственность раннера. Main спавнит только его.
  • Вопрос при blocked передаётся дословно. Пересказ — это уже интерпретация решения, которое принимает человек.
