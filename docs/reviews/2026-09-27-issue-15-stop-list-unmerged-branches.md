### P2

1. **Локальный `main` опережает `origin/main` на c2013d8.** Коммит сделан на локальном
   main (reflog `main@{0}: commit`). Для PR это не мешает: ветка несёт тот же коммит,
   а после squash-merge local main придётся выровнять по origin. Но так уже было в
   #34 (`main@{2}: reset: moving to origin/main`), значит паттерн повторяется: коммит
   в main, затем reset. Это расходится с разделом «Интеграция ветки», поэтому ветку
   стоит создавать до первого коммита. Выравнивать local main должна main-сессия
   после merge, а не reviewer.
2. **`followup.md` расходится с фактом**: «Local main = origin/main (5f8fd1a)» не так,
   local main = `c2013d8`. «#15 закрыт» и `[x]` в todo.md проставлены до merge PR.
   Если PR задержится, snapshot врёт. Лучше писать «#15 — PR открыт» и ставить `[x]`
   после merge (или пусть pr-shepherd делает post-merge stamp).

### P3

1. «Несмерженная» ветка не определена операционно. После squash-merge
   `git branch --merged` ветку не покажет, и `git branch -d` откажет. Для
   будущего guard (#23/#24) критерий нужно задать через состояние PR (merged),
   а не через git-ancestry. Для прозы стоп-листа этого хватает.
2. «Несмерженные ... теги»: теги не мержатся, поэтому формулировка к тегам
   семантически размыта. По факту удаление тегов остаётся запрещённым. Можно
   уточнить в #23.
3. `cli/internal/apply/tables_test.go:78`: комментарий «force-push и удаление
   веток — операции main-сессии» остаётся корректным, правка не нужна.
